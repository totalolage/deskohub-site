# PostHog-to-devbox trigger transports

Research date: 2026-08-28. This note uses public documentation, PostHog's public OpenAPI schema and source, and the checked-in generated client. It contains no production payloads or credentials.

## Recommendation

Earlier recommendation superseded on 2026-08-28. Poll PostHog's raw product APIs from an outbound-only devbox timer. Do not use PostHog Self-driving Signals or Slack as the machine trigger.

The selected production-only sources are new and reopened Error Tracking issues, Error Tracking spike events, and Logs alerts entering `firing` or `broken`. The direct intake contract is documented in [posthog-custom-agent-intake.md](posthog-custom-agent-intake.md).

The user accepted the direct API's known limitation: a resolved issue that reopens and resolves again entirely between five-minute polls can be missed. The collector must preserve issue state locally, refresh known active issues, use overlap pagination, and fail closed on partial pages. Slack remains an optional future alternative only if that missed-transition gap becomes a measured problem.

Minimal polling contract:

1. Run a systemd user timer every five minutes against EU project 204184.
2. Poll compact issues with a production filter and a 15-minute overlap. Refresh every locally known active issue so later reopens can be inferred from local state.
3. Poll spike events and Logs alert histories newest first. Use their provider UUIDs as occurrence keys.
4. Atomically claim a normalized, redacted occurrence before starting T3 Code. Never persist raw events, logs, credentials, access codes, or customer data.
5. Do not advance any watermark after an authentication, rate-limit, server, partial-page, or schema-decode failure.

## Failure policy and decision boundary

- Treat `401/403` as a credential/configuration incident, `429/5xx` as retryable with exponential backoff and jitter, and schema-decode failures as fail-closed. Do not advance local discovery state on a failed or partial page.
- Page until exhausted or until every result is older than the stored watermark overlap. Claim spike and Logs occurrences by provider UUID. Claim inferred issue transitions with the deterministic local keys documented in the intake contract.
- Refresh locally known active issues before discovering recent active rows. Skip a candidate that is no longer active, is outside the production filter, or already has a working job or open PR.
- Alert a human if the poller has not completed successfully for 15 minutes or if the active issue roster exceeds its bounded limit.
- Move to a managed pull queue only when multiple devboxes need atomic competing-consumer delivery, a formal dead-letter policy is required, or polling cannot meet a measured delivery goal.

Earlier research preferred native Signals because its reports are structured and deduplicated, and considered Slack as the common outbound alternative. Both recommendations are superseded. The selected design deliberately owns correlation and actionability in the local T3 Code loop.
