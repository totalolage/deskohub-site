# Adding a locale

Workspace paths are relative to `apps/deskohub-workspace`. The locale is added when every step below is done and these pass: the Workspace typecheck and full test suite, and the tests of every package the steps change (`bun turbo test --filter=@deskohub/i18n --filter=@deskohub/nexi --filter=@deskohub/workspace-customer-api --filter=@deskohub/workspace-admin-api` at least, golden contracts included).

1. **Registry.** Add the entry to `packages/i18n/src/locale-registry.ts` with every field ([architecture](architecture.md#the-locale-registry)). Give it a `fallbackChain` that reaches `cs-CZ`. Update the expectations in `locale-registry.test.ts`.
2. **Inlang settings.** Add the tag to `locales` in both Workspace projects, `project.inlang/settings.json` and `features/administration/i18n/project.inlang/settings.json`, in registry order. The two `inlang-project.test.ts` drift tests fail until both match.
3. **Glossary.** Add `references/glossary/<locale>.md` to this skill, covering every term ID in [terms.md](glossary/terms.md), and add the locale to the register (§2) and plural (§8) sections of [style-guide.md](glossary/style-guide.md). Translation starts after this.
4. **Catalogs.** Add `features/i18n/messages/<locale>.json` and `<locale>.json` in every area folder under `features/administration/i18n/messages/`, translated per [translation-workflow.md](translation-workflow.md) and parity-checked against `cs-CZ`. Compile both projects ([catalogs](catalogs.md#compiling)).
5. **Typecheck.** Run the Workspace typecheck and fill every per-locale map it names. Maps built with `mapSupportedLocales` or keyed by `Locale` or `SupportedLocale` turn a new locale into a type error until they have a value.
6. **Vercel headers.** Add the tag to the locale alternation in the `vercel.json` header route for locale pages. `vercel.test.ts` checks it against the registry order.
7. **Database.** The locale `CHECK` constraints come from the customer Inlang `locales`, so step 2 changes the schema. Generate the migration with `bun turbo db:generate --filter=deskohub-workspace`; `db/migrations/*_supported_locales_de_uk_sk/` shows the shape (one `CHECK` per locale column). Follow the migration folder-name rules in the `deskohub-repository` development reference.
8. **API contracts.** `CustomerLocale` and `AdministrationCampaignLocale` gain the tag, so the customer OpenAPI and administration wire-contract golden fixtures change. Regenerate them as their tests describe and review the diff for shipped clients.
9. **Legal documents.** Add `features/legal/locales/<locale>/` with `documents.tsx` (exporting `translation`: the documents and the notice that the Czech version governs) and `summaries.ts`, and register the locale in `features/legal/content.tsx`. Add the locale's translation date beside `documents.tsx`; it feeds the legal pages' sitemap `lastmod`. Record the new published versions in `features/legal/document-version.test.ts` and in `consentBannerDocumentVersions` (`features/legal/consent-banner-revision.ts`). Recording them changes the banner revision, which reopens the cookie banner once for every visitor.
10. **Fonts.** If the locale's `script` isn't covered by the default font, add it to the font mapping for scripts the default font lacks.
11. **Hand-listed tests.** Update tests that enumerate locales themselves (sitemap, hreflang alternates, the locale switcher, request-locale and proxy tests, and others the suite reports).
12. **Mobile (separate decision).** The mobile app serves only the locales its own Inlang project lists and doesn't read the registry. Adding a locale there means, under `apps/deskohub-mobile`, its `project.inlang/settings.json`, `messages/<locale>.json`, and the `AppLocale` union in `src/i18n/app-locale.ts`. See `deskohub-mobile`.

Nothing changes in Dotypos. Staff-facing text, such as Dotypos reservation notes and staff notifications, stays Czech for every locale. Operator-authored content (campaigns, reusable emails, discount labels) needs no new fields: the new locale reads it through its fallback chain ([architecture](architecture.md#content-that-falls-back-through-the-chain)).
